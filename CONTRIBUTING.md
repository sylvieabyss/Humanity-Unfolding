# Contributing to Humanity Unfolding

Thank you for wanting to improve the **one official Humanity Unfolding game**.

This is a **source-available, proprietary** project, not an open-source project. The owner retains final creative, technical, and release authority. A public GitHub fork used to prepare a contribution is not an authorized independent game release; see [LICENSE](LICENSE) and GitHub's Terms of Service.

## Ways to help now

1. Open an issue for bugs, design suggestions, documentation errors, accessibility concerns, or balance ideas.
2. Include reproduction steps, relevant system details, expected behavior, and actual behavior when reporting a bug.
3. Discuss major changes before implementing them. Approval of an idea is not approval to merge specific code.
4. Avoid posting passwords, personal data, exploit details, or confidential materials in public issues.

## Code and content contributions

**Do not submit substantive code, artwork, music, writing, or other copyrightable material for inclusion until the owner has approved a contributor agreement for that contribution.** The owner will establish that process before accepting external implementation work.

This protects both contributors and the project. A GitHub pull request by itself does not automatically assign copyright or grant unlimited relicensing rights. An agreement should clarify that contributors retain ownership while granting the owner broad, durable rights to integrate, modify, maintain, relicense, and distribute accepted work, including commercially if the project later changes direction. It should include appropriate assurances about originality and third-party licensing, and should be reviewed before use.

For any permitted submission:

- Submit only work you own or have explicit permission to license on the required terms.
- Disclose reused code, generated assets, models, libraries, fonts, audio, and their origins and terms.
- Never remove required third-party notices or imply the project's license overrides them.
- Keep each change focused, explain its motivation, and include testing notes.
- Follow formatting, architecture, and test conventions once published.
- Expect review, requested changes, or rejection at the owner's discretion.

## Reporting security concerns

Do not publicly disclose an exploitable security issue before the owner has had an opportunity to investigate. Use GitHub's private vulnerability reporting feature if enabled; otherwise ask for a private contact method without posting exploit details.

## Official releases

Only the owner or authorized maintainers designate official builds and releases. Community suggestions and contributions do not create a right to publish a separate Humanity Unfolding edition.

## Conduct

Be constructive, avoid harassment and personal attacks, and discuss the work rather than the person. Participation in official project spaces may be moderated.
